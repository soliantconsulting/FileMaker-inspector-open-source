# Inventory to register

**2026-09-16: the legacy file is retired.** `legacy/clockwork-inspector.html` and `docs/saxml-inventory.md` are history now; they remain in git. This mapping is the record of how each of the inventory's gap ids was resolved, not a live index of anything: the live source for what fm cannot read is `fm-adt-toolkit/gaps/register.json`, read by the Gaps tab and by `fm-gaps check`. Nothing here is re-derived from the legacy file any more.

One row per gap id from `docs/saxml-inventory.md`'s "Gap ids introduced" section (10 today). "Register entries and attributes" names `entry.id` / `attribute.name` pairs from `fm-adt-toolkit/gaps/register.json`, each an attribute with `reported: false` and no `wontfix` — a real gap by the register's own accounting. Most gap ids map to many register attributes; the list here is a representative sample, not the full set, except where the notes column says otherwise. Built by keyword search over a dump of every `reported: false, !wontfix` attribute in the register, then hand-matched to each gap id's description in the inventory.

Every gap id now resolves to a real register pair; there is no `OPEN ITEM` left. The last two were seeded on 2026-09-15 as register entries of their own, `calculation-tokens` and `plugin-call-sites` — both `op: none` entries whose probe is a `validate:calculation`, which is the op that comes closest to the question and answers none of it. `catalog-layout-options` was retired on 2026-09-14: fm's own layout flag table names both bits (confirmRecordSave, disableQuickFind), so the inventory rows became covered. On 2026-09-16 the fm 0.7.0 intake retired two more: `catalog-theme-styles`, because `read:theme` now lists and describes the file's themes (`css`, `colorPalette.swatch1..5`, `namedStyleNames`, `layoutsUsing`/`layouts`), and `catalog-relation-sort`, because `relation.{leftToRight,rightToLeft}.sortSpec.fields[]{field,order}` now reports the sort a relationship applies to related records; `catalog-layout-parts` survived in reduced form because `layout.parts[]` reported the parts but not their options word. On 2026-09-23 the fm 0.8.0 GA intake narrowed two more without closing either: `catalog-layout-parts`, because `parts[].pagination` and `parts[].rowState` report the Part Definition dialog on seven of the ten part kinds, and `catalog-portal-setup`, because `objects[].filter` and `objects[].sort` report a portal's filter and sort order — leaving the sort spec's two switches, the sort field's id and occurrence, and the allow-create bit.

| Gap id | Rows | Register entries and attributes |
|---|---|---|
| `catalog-file-metadata` | 5 | fm 0.8.0-beta.0 largely closed this: `read:fileOptions` reports the startup layout, login mode, toolbar flag, minimum version, stored credentials, and all file script triggers with their events and scripts. What is still a gap on `file-options`: `file-options` / "hide from host's file list (FileMaker clients)"; `file-options` / "hide from host's file list (WebDirect)"; `file-options` / "saved page setup orientation"; `file-options` / "saved page setup scale"; `file-options` / "saved page setup paper size"; `file-options` / "file script trigger enabled in Browse mode"; and the container element `Metadata` (structural, not a datum). |
| `catalog-calculation-tokens` | 4 | `calculation-tokens` / "tokenised variable references of a formula". fm 0.8.0-beta.0 partly closed this: sent `references: true`, `validate:calculation` now names a formula's fields (with their occurrence) and its custom-function calls. It still names no variable, so the four rows here — every one of them a `$$` read — are still gaps. That is why `ui/analysis/globals.js` counts mentions by tokenising calculation text and says so in `GLOBALS_NOTE`. The calculation-text rows on script step kinds (for example `step:186`'s) are `reported: true` on purpose — they are the text fm does give you, not the missing tokens. |
| `catalog-plugins` | 7 | `plugin-call-sites` / "plug-in function call site in a formula" — the inventory's gap itself: marking a *calculation call site* as a plug-in function call (`MyPlugin_DoThing()` inside a formula). The register entry probes `validate:calculation` on `BE_Version`; fm answers `calc_unknown_function` for a function no installed plug-in declares, which is the whole of what it can say about a plug-in call. The plugin-installed script step is tracked separately on `step:186` / "external plugin step parameter data type"; `step:186` / "external plugin step parameter type"; `step:186` / "external plugin step parameter show inline"; `step:186` / "external plugin step parameter show in line". |
| `catalog-modification-info` | 15 | `account:amazon` / "last modified by account"; `account:filemaker` / "last modified timestamp"; `field:text-normal` / "last modified by user name"; `script` / "last modified by account"; `table` / "last modified timestamp"; `relation` / "last modified by user name" — and every other kind (every `account:*` and `field:*` variant, `authorization`, `base-directory`, `custom-function`, `custom-menu`, `custom-menu-set`, `extended-privilege`, `external-data-source`, `persistent-store`, `privilege-set`, `table-occurrence`, `theme`, every `value-list:*` variant) carries the same three-attribute gap. `layout` is the one kind that already reports who/when (`modified.account`, `modified.timestamp`, `modified.by`), so it is excluded from this list on purpose. |

| `catalog-tags` | 8 | `layout` / "tag list"; `script` / "script tags". |
| `catalog-portal-setup` | 2 | `layout-object:portal` / "portal sort is maintained as records change"; `layout-object:portal` / "portal sort puts blank values last"; `layout-object:portal` / "portal sort field table occurrence"; `layout-object:portal` / "portal sort field id". fm 0.8.0 closed most of this: it reports the filter as `objects[].filter` and the sort as `objects[].sort.fields[]{field,order}`, so "portal filter calculation", "portal sort is switched on", "number of portal sort fields", "portal sort direction" and "portal sort field name" all became reported.
